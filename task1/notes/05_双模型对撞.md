# 05 · 双模型对撞：同一个 Agent，换一颗"大脑"

> 对应课程 Advanced 关「学有余力」：`.env` 切 `glm-5.3` ↔ `deepseek`，同一问题跑两遍对比。
> 关键认知：**LangGraph Agent 的"大脑"是可插拔的**——graph 编排（记忆/工具/子 agent）一颗螺丝不动，
> 换模型 = 换发动机。这正是"用 LangGraph 而不是裸调 API"的核心红利。

## 一、模型是怎么被"插拔"的？（原理 30 秒）

```
.env 里三行 ──服务启动时读取──▶ graph 初始化时创建模型客户端
  AGENTSEEK_MODEL=…              （之后每个请求都发到这个端点/模型）
  OPENAI_API_BASE=…
  OPENAI_API_KEY=…
```

注意：**改 .env 不会热生效**，必须重启服务（配置是启动时读进内存的）。

## 二、操作步骤（实测可复现，2026-10-14）

```bash
# ① 备份（强烈建议，方便切回）
cd /root/research_deepagent
cp .env .env.bak_glm

# ② 改三行（vim .env）
AGENTSEEK_MODEL=deepseek-flash          # 端点实际模型名（见下方"模型名考古"）
OPENAI_API_BASE=https://api.deepseek.com/v1
OPENAI_API_KEY=sk-你的key

# ③ 重启服务（先杀旧进程，再带完整 PATH 启动）
pkill -f agentseek; pkill -f seekdb; sleep 2
cd /root/research_deepagent
PATH=/root/.local/bin:$PATH nohup agentseek dev >/tmp/agentseek.log 2>&1 &
# ⚠️ 坑①：PATH 不带 /root/.local/bin 时，预检报 "fail uv: uv is missing" 直接拒启
# ⚠️ 坑②：pkill 后一定 sleep 再启，端口没释放会起第二个失败

# ④ 健康检查（看到 {"ok":true} 才算活）
curl -s http://127.0.0.1:2024/ok

# ⑤ 发射（想打哪发打哪发）
cd /root/ch02_lite && python adv_fire.py normal
```

### 模型名考古（避免踩的坑）

DeepSeek 网页/文档里叫 **V4.1-Flash**，但 API 端点的实际模型名要用
`curl https://api.deepseek.com/v1/models -H "Authorization: Bearer $key"` 查——
实际返回 `deepseek-flash` 和 `deepseek-v4-pro` 两个。**人读的名字 ≠ 机器收的名字，
以端点为准**（和 04 篇 schema 考古同一个思想：别猜，去源头看）。

## 三、normal 炮弹对撞结果（已替你跑完）

| 维度 | GLM-5.3（智谱） | DeepSeek-V4.1-Flash | 谁赢 |
|---|---|---|---|
| 忠实点单 `add` | ✅ 参数一字不差 | ✅ 参数一字不差 | 平 |
| 答案 | 21111.11 ✅ | 21111.11 ✅ | 平 |
| 耗时 | 9.7s | **3.6s** | DS 快 2.7 倍 |
| 消息数 | 4 条 | 4 条 | 平 |

结论：**给足数据的"乖题"上两家都满分**，差异只在速度。模型真正的分水岭在
边界题（empty 不给数字 / huge 天文数字）——那才看得出"性格"。

## 四、你来跑：把另外两发也撞一遍

```bash
cd /root/ch02_lite
python adv_fire.py empty     # ~40s，看点：翻盘找证据 or 直接反问？
python adv_fire.py huge      # 3-5min，看点：DS 数零数得比 GLM 准吗？
```

看点预告（对照 04 篇 GLM 的答卷）：

- **empty**：GLM 两轮分别"反问"和"翻盘后陈述"——DS 会走哪条路？
- **huge**：GLM 两轮全翻车（621 位 / 10^258）——DS 的 add 同样会被 schema
  拒收（schema 是 LangChain 从 `a: float` 派生的，**与模型无关**，这是框架层
  防御的优点）；看它自救路径和**最终誊写长数字**会不会也翻车。
- 跑完把结果回填到上面的表格里，这就是你自己的"模型选型报告"雏形。

## 五、切回 GLM

```bash
cd /root/research_deepagent
cp .env.bak_glm .env        # 或把 .env 里的注释行换回来
pkill -f agentseek; pkill -f seekdb; sleep 2
PATH=/root/.local/bin:$PATH nohup agentseek dev >/tmp/agentseek.log 2>&1 &
curl -s http://127.0.0.1:2024/ok
```

## 六、本节带走的三句话

1. **模型是插拔件**：编排不动，换 .env 三行 + 重启 = 换发动机——这就是框架的价值。
2. **配置改动必须重启才生效**，且重启有坑（PATH/端口），步骤要沉淀成文档。
3. **乖题比不出高下，边界题才见性格**——选模型要测它的"底线行为"分布。
