**deepagents 的虚拟文件系统 = Agent 的外置记忆 + 工作台 + 防洪堤 + 门禁**，四件套撑起了"长任务不失忆、大结果不爆窗、危险动作有闸门"。

## 我曾经想错的三件事（认知修正）

1. **"路由也是 glob 吧？"** —— 错。routes 是 startswith 前缀，glob 只属于权限系统。静默失效最坑人，离线探针是照妖镜。
2. **"read_file 会把文件全给我"** —— 错。默认 limit=100 行，超红线就地截断。"全量读取"从来不存在，只有"分段读取"。
3. **"大工具结果会撑爆上下文"** —— 只对了一半。框架会卸载到 `/large_tool_results/`，上下文里只留取件条。真正的风险变成了：**Agent 不知道要分段读，或者预览就足够误导它**。

## 与第 2 章的衔接

- 第 2 章的 planning middleware 管"想清楚"（todo 列表）；
- 第 3 章的 filesystem middleware 管"记得住、取得回、不越界"（草稿纸+档案柜+防洪堤+门禁）；
- 二者共同点：都是**把状态外置出上下文**，让模型的小脑袋只装"当下该装的东西"。

## 面试快问快答（自测通过标准：3 秒内开答）

- Q：虚拟文件系统解决什么？→ 上下文爆炸 + 过程不可追溯 + 多 Agent 共享工作台。
- Q：两种后端区别？→ State=内存快照易失可序列化；FS=真磁盘持久；Composite=按前缀分区混合。
- Q：大结果怎么治？→ read_file 超线就地截断带提示；其它工具超线卸载转存+取件条（头尾预览）。红线 20000tok×4=80000 字符。
- Q：权限怎么配？→ 三元组（操作,路径glob,模式 allow/deny/interrupt），deny 软拒可见，interrupt 硬停等人。
- Q：最难排查的坑？→ routes 前缀 vs 权限 glob 的语义分裂——静默失效类 bug 用离线探针打。
