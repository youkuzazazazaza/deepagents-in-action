# 01 · 第4章地图：中间件如何"改装"你的 Agent

> 本章对应原书第4章《规划与上下文工程》。所有结论都在 **deepagents 0.7.8 + langchain 1.4.3** 上实测过，证据在 `../evidence/` 目录。

## 一、先说人话：这章到底在讲什么

前一章（ch03）我们给 Agent 装了个"虚拟硬盘"（StateBackend + FilesystemMiddleware），让它能像人一样把中间成果写成文件。

但一个真实干活的人，光会写笔记还不够，还得会两件事：

1. **列计划**：干活前先写待办清单，干一步勾一步 → `TodoListMiddleware`
2. **控制记忆量**：聊了三天三夜，得把老黄历打包归档，只留重点 → `SummarizationMiddleware`

"中间件"就是干这两件事的**插件**。你把插件塞进 `create_agent(middleware=[...])`，Agent 的能力就变了——不用改一行核心代码。

### 大白话比喻：改装车

- `create_agent` 造出来的是**素车**（发动机=大模型，方向盘=工具调用）
- 中间件 = **改装件**：装导航（TodoList）、装行车记录仪（Summarization 归档）、装安全气囊（PatchToolCalls）
- 素车能开，但跑长途（长任务）就会迷路、爆内存、出事故

## 二、中间件到底改了什么？——三个"手术位置"

中间件不是玄学，它只能在**三个固定位置**动手术（源码里叫 Hook）：

| 手术位置 | 官方名 | 时机 | 谁在用（本章实测） |
|---|---|---|---|
| 进大门时 | `before_agent` | 整个任务开始前，先修整消息历史 | `PatchToolCallsMiddleware`（补悬空 tool_call） |
| 说话前/后 | `before_model` / `after_model` | 每轮调用大模型前后 | `TodoListMiddleware.after_model`（同步 todos 到消息） |
| 包住发动机 | `wrap_model_call` | 把"调模型"这整个动作包起来，请求可以整个被改写 | `SummarizationMiddleware`（0.7.8 版的做法，重点！） |

**最重要的版本差异（0.7.8 实测）**：老教程（包括原书部分插图）说摘要中间件是加一个 `before_model` 节点、直接改 LangGraph 状态。**0.7.8 不是这样了**——`_DeepAgentsSummarizationMiddleware.wrap_model_call` 的源码 docstring 白纸黑字写着：

> "Unlike the legacy `before_model` approach, this does NOT modify the LangGraph state. Instead, it tracks summarization events in middleware state and modifies the **model request** directly."

翻译：不动状态，只改"发给模型的那份请求"。后果见 `03_lab3_摘要与归档.md`——你在 `get_state()` 里看消息数根本不会变少，但模型实际看到的已经变短了。

## 四、本章最重要的 3 个认知

1. **规划不是提示词魔法，是状态字段**。todos 存在 Agent State 里（和 messages 平级），模型靠 write_todos 工具读写它。状态在，计划就在；状态丢，计划就丢（所以 lab2 必须配 Checkpointer）。
2. **摘要≠删消息**。0.7.8 的摘要=①把旧消息原文写进 backend 文件归档 ②给模型看的请求换成"摘要+最近几条"。状态里的消息列表可以原样躺着——"账本"和"给模型看的纸条"是两回事。
3. **全家桶 vs 自己组装**。`create_deep_agent()` 预设默认把 TodoList+Filesystem+Summarization+PatchToolCalls 都装好了；自己 `create_agent()` 组装时，**保险丝（Patch）和存档（Sum 的 backend 参数）都不会自动有**，裸奔跑长任务必翻车。
