# 06 · 避坑清单（全部实测翻车，按痛程度排序）

> 环境：deepagents 0.7.8 / langchain 1.4.3 / langgraph 最新 / Python 3.12 (WSL)

## 坑1 ★★★ 摘要中间件"装了不干活"

- **现象**：挂了 SummarizationMiddleware，消息数照样涨，没有任何报错
- **根因**：`trigger` 默认 `None`，永远不触发
- **修法**：显式传 `trigger=("messages", N)`（或 token 版 `("tokens", N)`）

## 坑2 ★★★ 没挂 FilesystemMiddleware → 摘要静默降级

- **现象**：trigger 设了，日志出现 `KeyError: 'files'` + UserWarning `Older messages will not be recoverable`，历史原样膨胀
- **根因**：0.7.8 摘要归档环节要把老消息写进 backend 的 `files` 状态，那是 FilesystemMiddleware 的地盘；没有它，中间件不敢删原文（删了找不回），整个摘要动作放弃
- **修法**：Summarization 和 Filesystem 成对出现（用 `create_deep_agent()` 天然成对）；排障搜日志关键词 `will not be recoverable`

## 坑3 ★★★ PatchToolCallsMiddleware 导入路径

- **现象**：`from deepagents.middleware import PatchToolCallsMiddleware` → ImportError
- **根因**：它藏在**子模块**里，顶层没重导出（FilesystemMiddleware/Skills 等倒是顶层就有，坑就坑在不统一）
- **修法**：
```python
from deepagents.middleware.patch_tool_calls import PatchToolCallsMiddleware
```
- **教训**：import 报错先 `pkgutil.iter_modules(pkg.__path__)` 列子模块，别凭印象猜

## 坑4 ★★ 悬空 tool_call 的 400 报错

- **现象**：`An assistant message with tool_calls must be followed by tool messages…`
- **根因**：历史里有 tool_call 没配对结果（进程崩过/手工拼历史）
- **修法**：挂 PatchToolCallsMiddleware（保险丝自动补 ToolMessage）；或写入历史前自己校验配对

## 坑5 ★★ todos 消失≠中间件坏了

- **现象**：二次 invoke 后 `result['todos']` 变 None，以为 TodoList 失效
- **根因**：没配 Checkpointer，每次 invoke 都是新生命（lab2 实验一）
- **修法**：`checkpointer=InMemorySaver()` + 固定 `thread_id`；生产换 SqliteSaver

## 坑6 ★ 书的版本 ≠ 0.7.8 的行为

- 书里经典版 SummarizationMiddleware：在 before_model 里把 state.messages **替换成**一条摘要消息（能看到 messages 变短）
- 0.7.8 实测：**改模型请求不改 state**（wrap_model_call 包裹层），原文归档进 backend 文件，`len(messages)` 未必下降
- **教训**：读书时机制对不上号，先 `inspect.getsource()` 看当前版本源码，以实测为准

## 坑7 ★ 对照实验的"隐式全局变量"

- **现象**（lab2 翻车实录）：快照函数里写死读 `cfg`，实验三换 `cfg2` 后打印的还是旧线程状态，差点得出"thread_id 没用"的错误结论
- **修法**：读状态的函数必须把 config 当**参数**传；对照实验的每组只允许一个变量
